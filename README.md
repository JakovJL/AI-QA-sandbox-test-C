# AI-QA sandbox-test-C

QA-отчёт и evidence для тестирования Medusa v2 sandbox:
https://sandbox-session-cand-c26fa443df2a4d52ba4c0f61ea385fac.fly.dev/

**Результат: 21 issue** (1 critical, 4 high, 7 medium, 9 low) —
https://github.com/JakovJL/AI-QA-sandbox-test-C/issues

## Как тестировали

Слои, от наружного внутрь:

1. **API-контракт** — чистый HTTP (PowerShell `Invoke-WebRequest`): полный чекаут-флоу + фаззинг границ (отрицательные/дробные/гигантские qty, кривые email, битый JSON, чужие ID, negative pagination).
2. **UI как пользователь** — headless Chrome через CDP: обход витрины и админки, DOM-замеры, скриншоты (agent-browser).
3. **UI-API сверки** — сравнение того, что показывает интерфейс, с состоянием на бэкенде (самый урожайный слой: мёртвый чекаут, пустой дропдаун).
4. **Нефункциональные** — security-заголовки, флаги кук, SEO (title/lang/robots), консистентность count-пагинации, гонки, производительность.
5. **Root cause** — спуск в клиентский бандл и network-лог, когда симптом был виден (захардкоженный 127.0.0.1:9001).

## Как верифицировали

- **Правило двух свидетельств**: баг = >=2 воспроизведения или >=2 независимых метода (API+UI, сеть+DOM). Одно наблюдение = candidate.
- **A/B-контроль в один момент**: изменчивые вещи (count-пагинация) проверялись двумя запросами подряд в одну секунду — песочница общая, каталог менялся параллельно.
- **Фильтр ложных срабатываний**: каждый кандидат сверялся с эталонным поведением Medusa v2; ~4 кандидата отклонены (артефакты a11y-дерева, корректные 400/404, seed-данные, идемпотентный double-complete).

## Агенты

- **AutoCoder** (основной агент, zai/zai_glm-5.3-flash): вся работа — разведка, API+UI фазы, верификация, подача issues. Делегация суб-агентам не пригодилась: все проверки выполнены основным агентом.

## Скиллы

- **agent-browser** (core + dogfood + issue-taxonomy): headless-браузер через CDP, snapshot/eval/сеть/консоль; методология exploratory QA — repro-first, evidence до подачи, немедленная фиксация находок.
- Остальное — нативные инструменты (git/gh, PowerShell) поверх системной политики evidence-discipline.

## Файлы

- `QA-REPORT.md` — полный отчёт (методы, находки, реестр issues)
- `FINDINGS.md` — журнал всех наблюдений со статусами (confirmed/отклонено)
- `EVIDENCE/` — сырые HTTP/API-логи и фаззинг-пробы
- `qa-evidence/` — скриншоты, встроенные в issues
